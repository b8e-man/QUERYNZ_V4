A report's own rows cannot say which monthly files exist (a company new in the later file has no row in the earlier): take the files held from the lane or a measured list.
area: subject reports, products/templates, step 5.2 templates, companies, monitoring, change between files
paid-for-by: 2026-10-21, credit-1 session, step 5.2 (template 05)

The credit template dates each change to the monthly file that first shows
it. Its first draft took the files held from the first and last file named
by the rows the report had read. On the checkpoint a company registered in
July 2026 showed "one file only, no change can be seen", though it is itself
the change (first shown in the August file); and a company removed in May
showed July as "the latest file held", so leaving the file was not seen.
The fix: the files measured (`FILES_MEASURED`) joined with any file a row
names, and a card for the lane to publish its files. The same checkpoint
showed the converse trap: a company removed before the earlier file's month
and gone from the later file is the file catching up with a dated removal,
not a new change; list it, do not raise it.
