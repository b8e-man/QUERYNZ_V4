Never pair a column of names with a column of figures by their order: a name shifted by one row still adds to the part's total, so the reconciliation that guards every other route cannot see it.
area: reading documents, EC party returns, Part A donors, OCR, page reader
paid-for-by: 2026-10-19, party-returns session 2, step 4.1 tranche 2

The page reader sometimes reads a table down its columns: every name and
address, then every date, then every amount. Pairing them in order passed
the to-the-cent check on ADVANCE NZ 2020 while an address line ("…, being
the address for …") sat as a donor and every amount below it belonged to
the row above. Rows are paired only by structure: a table row, a printed
row number, the text layer's geometry, or a stacked run where each amount
closes its own row. A column-by-column page refuses its part. The same
night showed two more ways the sum is blind: a "see attached schedule"
row carries the schedule's total (it doubled National 2023), and a page
subtotal under the table reads as a donor unless it is recognised by
equalling the figures above it.
