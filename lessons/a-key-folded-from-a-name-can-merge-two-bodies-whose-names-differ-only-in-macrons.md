A key folded from a name (macrons off) can merge two bodies: where one key's pages print different names with the macrons kept, key each name by the first page that prints it, in the load, the one step that sees every page.

Why: the iwi directory keyed an organisation `tkm/org/<name folded>`. Ngāti Hāua Iwi Trust (Upper Whanganui, a
mandate) and Ngāti Hauā Iwi Trust (Waikato, the 2014 Act) folded to one key, so the load merged them into one row
named for the first page, listed under both iwi and carrying both settlements. The reader sees one page at a time and
cannot know; the merge saw both and trusted the key. In Māori a macron changes the word, so a fold that drops it is a
match rule, not an identity.

How to apply: where rows from several pages merge on a folded key, compare the names as printed (macrons kept, case
and spacing not) before merging; if they differ, split and say how many keys split in the load's counts. Keep the
plain key for the rest so nothing else moves (here one row of 2,696 changed key). Pin the pair as a hard case on the
stored pages and add a case where the same name on two pages stays one body. The same holds for a shared identifier
used as a row's key: a key names one row, and a settlement shared by eight bodies goes in its own column beside the
row's key (`settlement_key`), never as the key.
