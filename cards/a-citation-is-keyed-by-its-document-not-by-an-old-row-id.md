# A citation is keyed by its document, not by an old row id
kind: finding
state: open
use-case: 1
session: comparison
opened: 2026-10-20

The frozen site wrote one citation file per row keyed by the old row id
(`cdon-461330`), which changed every night; 10,569 of them today. The
rebuilt site keys a citation by register, document hash and place on the
page; 1,300 today. No path is shared, so the comparison counts the two
sets and compares no citation file by content: the citations are checked
where the pages carry them.

Which side is right: neither is wrong; the rebuilt key is stable and the
old one was not. The count gap (10,569 against 1,300) is mostly candidate
returns and Part A rows not yet read (their cards). Owner: site.
