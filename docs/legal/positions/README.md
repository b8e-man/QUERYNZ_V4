# The one-page legal positions

Hard limit 9: before a new class of source is captured, its one-page legal
position is written here, from the four questions of hard limit 4. The
fetch gate (`support/fetchgate`) refuses any host that no position on file
names, so a lane cannot fetch first and ask later. A lawyer reviews these
pages before anything is sold (track G, `docs/legal/before-selling.md`).

One file per class of source, `<class>.md`, and it must carry a line

    hosts: host.one, host.two

naming every host the position covers (a parent domain covers its
subdomains). The page answers, in plain words and in this order:

1. **Is the page open?** Reached without getting past a lock, a login that
   is not ours, a challenge or a block. (A headed browser shown no
   challenge may read a page; shown one, it stops.)
2. **Is storing it lawful copying?** The statute or licence the material
   is published under; what copying it permits; whether the register's own
   Act limits use.
3. **What terms did we accept?** The site's terms, and whether they bar
   what we do (commercial reuse, machine reading).
4. **What does privacy law, or the register's statute, limit?** Personal
   information in it; what may be shown; what must be held apart.

Then: the stated crawl delay if any, the floor we use, and the date and
author of the position. Nothing in step 1 captures, so this folder holds no
position yet; the first lanes of step 4 write theirs before their first
fetch.
