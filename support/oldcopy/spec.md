owns: the copies of the old estate's tables, `old_<database>_private.<table>` in `querynz_v4` (`<schema>__<table>` when the old schema is not `public`; regenerable, private by the suffix because the old databases hold home addresses); the never-wiped ledgers in `oldcopy_private` (`batches`, `cursors`, `refusals`, `files`, `file_cursors`; tables.sql); the old files' landings in the document store, through `support.docstore.landing.land` only (ruling 160)
reads: stream I's inventory `docs/research/old-estate-inventory.json` (NEW and PARTLY only; HELD, DERIVED, OUT never); the old databases `incoming_news`, `nzbn_canonical`, `extractions` through the read-only old login in read-only repeatable-read snapshots, never written (hard limit 22); the old file stores the inventory names, read only
publishes: nothing in `pub`; no row content is ever printed, only table names, counts and md5s
outside check: every batch is counted and hashed at the source (md5 over each row's md5 in key order, one snapshot with the rows streamed) and again in the new table before its commit; a table with no usable key and no bigger than 1 GB is copied whole in one such batch (its md5 over the rows' md5s sorted; run again, it replaces the copy), a bigger one is refused; a disagreement rolls the batch back, writes a failed ledger line and stops the table; `--dry-run` measures a table at the source alone
jobs: `qv4-old-copy-tables` (pieced, one piece per table, `tables --pieces`), `qv4-old-copy-files`; both on a night clock, starting no batch outside 22:00 to 05:45 NZDT, one batch at a time; both `enabled = false` until the integrator has reviewed the inventory and checked the disk

## Consumed (ruling 162)

`python -m support.oldcopy.consumed` (job `qv4-old-consumed`, daily after the night's copies) classes every table of the three old databases, read from their live catalogues, and every old tree the off-site copy sends: copied (caught up, no failed batch standing, the rows counted the same at the source and in the copy now; a store's every wanted file on disk in the ledger), held (stream I's evidence), let go (rulings 161, 164), waiting, or not held. It writes `<live>/checks/old-consumed.json`; `ready` is true only when nothing waits and nothing is not held. The old off-site copy stops on Arthur's word given on that proof, never by the check. To leave nothing behind, the inventory marks the small DERIVED tables `keep` and the old record trees (audits, eras, review, the units, the staging downloads with no store) `every_kind` stores, which land every file whatever its kind. A store whose walk has caught up is walked again from the start each night, so a file written since is found; a file it holds costs a lookup and no second ledger line.
