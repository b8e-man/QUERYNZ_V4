owns: schema `mcpsource` (`cursors`: per corpus, the MCP's records taken and the change feed's stamp; `arrivals`: per record taken, its corpus, `seq`, id, url and the hash it landed as, `new` false for an unchanged re-arrival; `catch`: the catch log, a line per record not landed, with its stage, reason and the day a later run landed it; `drift`: each field or type the recorded shapes in `shapes.json` do not hold; `files`: one row per file a record points at, a `capture` block with a sha256 and a content type, with its state: waiting, landed, held or caught, and the `download` calls spent on it); the documents of source `query-nz` in `docs` (through the landing wrapper only): each record's JSON, keys sorted, no spaces, without `seq`, named `<corpus>/<id>` and by its `url`; a record served changed is a second document under the same names; and each file a record points at (ruling 126; today the courts corpus: case pages, judgment PDFs, media releases), its bytes as the provider captured them, landed by hash under the record's `url` with the record's content type and the capture's fetch time
reads: the ingest MCP `query-nz-ingest` (Arthur's provider, rulings 78, 94, 96) at http://127.0.0.1:8646/mcp through the tunnel unit `qv4-mcp-tunnel`: `corpora`, `records` and its change feed `changes` (records re-processed in place, their `updated_at` moved, followed from the newest stamp read, `cursors.changes_since`), and `download` (format `raw`: a meta block and the file as an embedded base64 resource; metered per call, so a file whose hash the store holds is named from disk and never fetched, and a file caught is not asked for again until `--retry-caught`; never the text resource `qnz-text://`, the text is ours to read from the bytes), never its `search` or `measure` in the pull; one request at a time, 200 records a page, a pause between pages, each call under a time limit, a slow or dropped call waited for and asked again (30 s doubling to 10 minutes, six tries)
publishes: nothing in `pub`; the documents are read by the lanes over them (`registers/beehive`; `registers/parliament`, `registers/ministers_diaries`, `registers/hansard` to come, the last for the seventh corpus `parliament-hansard-debates` too; `registers/courts` reads the courts corpus's files by hash, `mcpsource.files` by `capture_sha256`, as its primary source from `courts-2`), each taking as a record's current version the document the pull saw last (`mcpsource.arrivals` by `landed_at`), never the highest `seq`: after the MCP removes records, a re-rendered record comes back at a lower place
outside check: each corpus's cursor against the MCP's own `ingest_cursor` from `corpora`, with every record taken either an arrival or a catch line, and every file pointed at landed, held, caught or still waiting on the budget (`python -m support.mcpsource` prints all of it; red when a corpus fails, a record or a file is caught or a field is new to us; files left waiting are not red, the next night takes them); `tests/test_mcpsource.py::test_the_live_server_still_serves_the_recorded_shape` (slow) holds the live server to `shapes.json`, and `test_the_live_server_still_delivers_a_file_as_recorded` (slow, one metered call) holds the `download` answer to its recorded shape and the bytes to the record's hash
