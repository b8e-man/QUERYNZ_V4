# support/scheduler — the scheduler (plan step 2)

The one service that places every job on a graphics card or on the
processor. `python -m support.scheduler` is the command line (`check`,
`tables`, `status`, `enqueue`, `probe`, `worker`, `report`, `memory`, `rereads`, and `night open|close|status`:
Arthur's word on the night window, one file under <live>/scheduler/, never a commit).
The module docstring in `__init__.py` names the pieces; `spec.md` is the
five-line spec; `jobs.toml` is the job catalogue (every `qv4-` job, the founding four on the
queue's clock among them, and the standing server's night window `[night_window]`, ruling 129:
`night.py` is its clock, `cards.Manager.night_tick` acts on it; since 31 October a pieced job's `pieces_command`, a job's `then` and
`threads`: the chain runs itself, `worker._run_pieces` keeps `concurrency` pieces in flight within the profile's `streams`) and `profiles.toml` the four model profiles of
step 2.15 plus which model server the cards run (`[server] binary`; a
profile may name its own with `binary`, and then loads only where the probe
lists that program). Extended from the old fleet service
(`ops/fleet` at `v3-frozen-2026-10-18`); its tests were carried first.
