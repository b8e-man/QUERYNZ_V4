owns: `support/recipes/weights.jsonl` (each model weights file's sha256 by file and size, append-only, written by `python -m support.recipes.serving weights --write`); `<live>/recipes/servings.jsonl` (every serving record a worker saw, keyed by its serving id, append-only, never edited); later tranches add the recipe, golden-set and trial ledgers beside them (README.md)
reads: the installed `qv4-*` unit files in the user unit folder and the box's QV4_ environment file (only QV4_ names, never one naming a key, token, password or secret: hard limit 1), podman's image id for each image a unit runs, the weights files' sizes, the scheduler's profiles
publishes: the serving id each reading carries (`QV4_SERVING_ID` from the worker into `support.reader.Reading.serving`); `serving.resolve(id)` names what it meant; `python -m support.recipes.serving show` prints this box's standing servers and their ids
outside check: an id resolves in the servings ledger; one serving reads the same on both boxes (the box's name is no part of it); a weights file the ledger lacks is named `unhashed`, and a serving that could not be read is stamped `unmeasured: <why>`, never passed as known
jobs: none of its own; the worker's card manager writes the servings ledger as servers stand and load
